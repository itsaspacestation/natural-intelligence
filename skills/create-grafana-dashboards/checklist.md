# Dashboard checklist

Back to [`create-grafana-dashboards`](SKILL.md). Tick every line before handing over.

## Context

- [ ] Infrastructure as code found: the resource, the module it calls, the environment overlays
- [ ] Variant recorded: engine and version, instance class, serverless or provisioned, replicas, zones
- [ ] Switches recorded: log exports, parameter groups, monitoring features on or off, agent intervals
- [ ] Module defaults read, or listed as unknowns when the module source is out of reach
- [ ] Application side checked: client instrumentation that already covers part of the service

## Reference

- [ ] Official monitoring page found and its URL recorded
- [ ] Every metric on the page read; kept or dropped with a reason
- [ ] Dropped families named in one README line
- [ ] Optional or paid sources identified, each with its own page

## Quotas and limits

- [ ] Service quotas page found; its URL in the README under the metrics reference and in the dashboard links array
- [ ] Per-quota console link (the vendor's quota code) in the description of the panel that draws it
- [ ] Every quota that throttles or stops the service listed, with its default value and whether it is adjustable
- [ ] Each quota mapped to the metric that consumes it, or to a usage metric when the service publishes one
- [ ] Each quota mapped to the rejection counter the service emits when it is hit; none emitted, said in the README
- [ ] Limit drawn on the consumption panel: second series, quota math, constant series from a text box variable, or threshold line
- [ ] Limits that depend on the instance class or a parameter carry the vendor's formula in the panel description
- [ ] Rejection counters in the errors position of their row, red bars
- [ ] Account-level quotas in their own row when the service publishes usage metrics

## Metadata

- [ ] Title: vendor, service, data source, for example "AWS RDS CloudWatch"
- [ ] Stable uid in kebab case derived from the title
- [ ] Tags: data source type and vendor
- [ ] Description: one sentence naming the namespaces or metric families used
- [ ] Links array: the reference page, the source repository folder, the published dashboard
- [ ] Time range and refresh fit the metric period: one minute for CloudWatch, five seconds for Prometheus
- [ ] Shared crosshair on

## Variables

One per line, in this order, hidden unless the user needs it:

- [ ] Data source, hidden
- [ ] Region or environment, hidden, resolved from the data source
- [ ] Period or interval, visible, the only one the user touches daily
- [ ] Resource selector from a dimension or label query, one per level, each filtered by the previous
- [ ] Log group or stream, multi-value, regex on the selected resource
- [ ] Text box filter for the logs panels, hidden
- [ ] Top-N and percentile selectors when a panel uses them

## Rows

- [ ] One row per section of the reference page, in the page's order; a section over twelve panels splits into sub-rows named after it
- [ ] Row title carries the period when its panels do
- [ ] Panels inside a row: rate, errors, duration, then saturation and limits; USE order only when the section has no request metric
- [ ] Paid or opt-in sources in their own collapsed row, title says optional
- [ ] Logs row last, before the optional rows

## Panels

- [ ] Title names the metric family and the period
- [ ] Description holds the metric's documentation link when the page has anchors
- [ ] Unit set from the page: seconds, milliseconds, bytes, percent, count per second
- [ ] Minimum zero on counts and durations
- [ ] Errors as bars in red; everything else as lines
- [ ] Legend as a table at the bottom with one calculation: sum for counts, max for gauges
- [ ] Legend label built from the dimension, metric name, and statistic, so series stay readable with the All value
- [ ] Each target names the data source variable, the region variable, and the period variable
- [ ] Exact dimension match on, wildcard only on the dimensions the reference says vary
- [ ] Panels scoped by the parent's dimension pair, never by a wildcard on a child dimension
- [ ] A limit drawn as a second series where the page documents one
- [ ] Documented sentinels and caps explained in the panel description, with the page that documents them
- [ ] Collapsed rows stacked with distinct y offsets so their panels do not overlap when expanded

## Build

- [ ] JSON generated by a script outside the repository, rerun after every change
- [ ] Lint on the output: unique ids, no grid overlap, period and region on every target, no datasource uid, metric names present on every metric target
- [ ] Dimension listing per panel reviewed once before hand-over

## First live view

- [ ] Legends read for resources outside the selection
- [ ] Math expressions, constant series, and threshold lines render
- [ ] Empty log panel checked over a week before the query is changed
- [ ] Defects fixed in the generator and the JSON re-imported before screenshots

## Logs

- [ ] Logs row reads the log group variable and the text filter
- [ ] Error-log panel filters on the engine's error vocabulary
- [ ] Log-derived metric panels parse documented line formats only

## Cost

- [ ] Pricing page fetched for every paid or opt-in family; estimate scaled to the user's resource count
- [ ] Log substitute identified, with its own scan cost and what it loses
- [ ] Preview table shown and the user's choice recorded before building the rows
- [ ] Log-derived panels in the main rows, paid family in the collapsed optional row
- [ ] README says which panels are free, which need an opt-in that is charged, and the estimate shown

## README

Written from the template linked in [`create-grafana-dashboards`](SKILL.md):

- [ ] Reference line first, URL identical to the dashboard links entry
- [ ] Deployed variant section naming the infrastructure as code and its unknowns
- [ ] No vendor figures in the README: quotas, defaults, class sizes, and prices change; link the page that holds them. A figure the dashboard needs lives in a variable default or a panel description, next to its reference
- [ ] One heading per row, same order as the dashboard
- [ ] Paid rows say so and link their own page
- [ ] Setup section when the source needs instrumentation packages or an agent

## Screenshots

Claude cannot render Grafana. Ask the human, by name of file, raw and full width:

- [ ] `0_Header.png`: the dashboard top with variables and the first row
- [ ] `<n>_<Row>.png`: one per row, numbered in row order; `<n>_<Row>_1.png` and `_2` for a long row
- [ ] Collapsed optional rows expanded for their image, even when empty
- [ ] A logo image for the folder when the repository uses one, unlinked when the siblings keep theirs unlinked
- [ ] Anonymised before saving: identifiers, account ids, breadcrumb path, data source name, log groups, avatar
- [ ] Patches sampled from the background colour, text redrawn at the original size, result viewed
- [ ] Every image linked in the README exists in the folder, and every file in the folder is linked or is the logo

## Publish

Template form, checked before the first commit:

- [ ] `id` is null and `version` is 1: no trace of the Grafana instance it was built on
- [ ] No datasource uid in any panel or target: every reference goes through the datasource variable or an input
- [ ] Inputs declared for every datasource an importer must pick; requirements list the datasource plugin, panel types, and Grafana version
- [ ] Links array holds the reference page and the repository folder, nothing else yet

Two commits, because the grafana.com id exists only after the first publish:

- [ ] First commit: the template, the README, the screenshots
- [ ] Publish on grafana.com, record the id
- [ ] Second commit: the grafana.com link added to the links array, the README's published link, the id in the README header if the repository shows one
- [ ] Folder holds the JSON, the README, the logo, and the screenshots only
